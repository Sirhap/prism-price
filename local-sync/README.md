# 本地同步

本目录的 `config.env` 记录目标站点和密钥：

```dotenv
API_BASE=https://parity.sirhao.top
INGEST_SECRET=目标服务器配置的密钥
SYNC_INTERVAL_MIN_MS=1000
SYNC_INTERVAL_MAX_MS=2000
```

配置文件不应提交或分享。若不存在，可从 `config.example.env` 复制；环境变量优先，密钥为空时兼容项目根目录 `.dev.vars`。Node.js 需支持 JSON 模块导入（建议 Node 22 以上）。

```bash
npm run sync:local -- --shop=King                 # 仅预览
npm run sync:local -- --shop=King --apply         # 同步一店
npm run sync:local -- --apply --shard=1/3        # 第 1 片
npm run sync:local -- --apply --shard=1/3 --resume # 继续同一轮
```

不指定店铺或分片会处理所有支持的已收录店铺。按店铺 ID 的 SHA-256 稳定分片；不同地点约定相同总数，每个地点使用不同序号，例如 `1/3`、`2/3`、`3/3`。**分片只避免店铺重复，不协调不同机器的请求速率**；同一出口 IP 的进程不要并行运行，不同出口同时运行也会叠加源站压力，建议错峰。分片期间总数不要变，新增店铺在下一轮覆盖。

默认并发 1，所有店铺对源站的请求共享间隔，默认在 `SYNC_INTERVAL_MIN_MS` 和 `SYNC_INTERVAL_MAX_MS` 之间随机取值（1～2 秒）。环境变量可覆盖配置，`--interval-ms=5000` 优先于配置并使用 5～6 秒；最小值不得低于 100 毫秒。不同进程不共享限速器。单店遇 403、429、验证页等源站风控信号时立即跳过，不重试、不删除、不记录完成，继续下一家；所有请求仍受间隔限制。目标站鉴权失败或限流时停止整轮。`--limit=6` 可小批试运行；续跑须保留相同目标、分片、店铺选择和 limit。各片默认独立续跑文件，`--checkpoint=路径` 可覆盖。新一轮不要加 `--resume`：每轮随机选择起点并绕回遍历，降低固定顺序反复中断造成后段长期未更新的概率；随机起点不能保证某段一定处理到，续跑会保留起点并跳过已完成店铺。

未变化的快照不推送；源站失败或已检测到不完整快照时不会覆盖该店。脚本不自动新增店铺或设置定时任务。采集数量异常减少但源站声称完整时，仍可能被视为商品下架。

可通过 `node local-sync/build-kit.mjs` 在 `output/ldxp-sync-kit.tar.gz` 生成可迁移包，包含同步所需代码及 Skill，不包含配置和密钥。把包交给其他环境后，让接收方自行安全配置密钥；不要把真实 `config.env` 或 `.dev.vars` 打包发送。

`--apply` 正式同步时，对源站店铺信息接口明确返回“店铺链接不存在”或“店铺不存在”，以及完整采集后无可收录商品的店铺，默认调用目标站删除接口；另加 `--delete-unavailable` 后，“商家已被关闭交易”也会触发删除。该操作同时删除店铺、商品报价及历史快照。商家封禁、访问限流、验证码、网络错误或其他异常不会触发删除。使用前应确认删除范围和备份；未加该选项时关闭交易只记录失败。若源站关闭交易是暂时状态，删除后需要重新收录才能恢复。

如需测试更短间隔，可配置 `SYNC_INTERVAL_MIN_MS=500` 和 `SYNC_INTERVAL_MAX_MS=1000`。默认仍是 1～2 秒。`--interval-ms=500` 表示 500～1500 毫秒，精确控制上下限请使用配置文件。

结果中的 `failed` 仅计实际失败的店铺，`riskSkipped` 记录源站风控跳过数量（同时包含在 failed 中），`unprocessed` 计目标站拒绝后尚未处理的店铺；`alreadyAbsent` 表示删除时目标明确返回店铺已不存在，不重复删除并记录断点。普通 HTTP 404 不会被忽略。用 `npm test` 执行离线测试，无需真实密钥或访问源站。

无可收录商品指经源站完整采集及现有占位商品过滤后的商品数为 0；正式同步会删除店铺及其历史，预览只提示。源站可能误报空数据，删除后须重新收录才能恢复。

缺货商品仍保留，库存为 0 仅表示采集时缺货；不会因为全部暂时缺货而删除店铺。

超过 2000 件时，仅发送前 2000 件并提示；支持部分同步的目标站会保留未发送的旧商品。目标站未声明支持时，脚本会停止该店以避免截断覆盖。

## 16688 和 KA123 本机采集

支持在运行脚本的机器上采集 16688 店铺详情与商品列表及 KA123 公开目录，使用相同的请求间隔、风控跳过和断点。由于源站未提供可信商品总数，仅以部分更新推送，不删除未返回的商品；空列表或字段异常视为失败，不触发店铺删除。目标站必须支持部分同步，并在同步清单中包含相应店铺。尚未适配的第三方系统不能按联动接口推测处理。
